# v2.9.1 Preview 1 — test debrief (11 October 2026)

## Outcome
Desktop/relay preview implemented and packaged. Dedicated Enfusion sender is source-only and experimental, pending engine compilation and real dedicated-server validation. No updated Workshop package or stable GitHub release was published by this work.

## Automated tests
- Before implementation: all 88 existing planner tests passed. Initial sandbox run blocked two loopback connections; the permitted networking run passed, without altering tests.
- After bridge implementation: all 98 planner tests passed (88 existing plus 10 dedicated/profile/lifecycle tests).
- Standalone relay: all 4 existing tests passed against the extended backward-compatible service.
- Full-map change: actual packaged Electron test passed; targeted 18-test core/localization/render/startup suite passed. Final complete-suite result is recorded in test-evidence/planner.txt.
- Existing tests were retained. Sarge's expected topic count was updated from 29 to 32 for the three new fully translated guides.

New checks cover profile CRUD, persistence and secret filtering, failed storage atomicity, invalid endpoint/options, explicit v2 sessions, permitted entity IDs, duplicate and older revisions, expiry/authentication, malformed/oversized payloads, lockout, interruption/recovery, disabled and exhausted retries, replacement connections, stale watchdog during a pending request, and delayed pairing after Stop.

## Packaged application tests
Used isolated temporary user-data directories, never the user's live plan/profile.
- Offline startup, profile create/edit/delete/export and persistence after reload.
- Actual bundled relay + Cloudflare Quick Tunnel, with valid protocol-v2 position updates through public HTTPS. This was a JavaScript sender adapter, NOT Arma Reforger.
- Marker creation and movement; setup fields; manual Stop and clean reload.
- Imported Operation Sea Serpent (29 units) remained byte-equivalent as parsed mission JSON before/after updates and export. Profile files contain no pairing token.
- New Sarge topic opens the correct Live bridge settings.
- Full map uses the window dimensions and hides header/sidebar/tools; native document fullscreen, F11, Escape and Show menus all tested.
- An uncommitted Callsign field survives Full map/restore. Mission remains unchanged. Reload returns normal menus.
- No renderer page errors observed.

## Performance observation
Same 400-unit fixture, bundled offline terrain, wheel zoom plus keyboard pan:
- RC2: 53.82 FPS average; p95 frame interval 16.9 ms; two frames above 50 ms.
- Preview: 56.42 FPS average; p95 16.9 ms; two frames above 50 ms.
Both loaded 16 tiles and reached the same viewport. This is a short local sample, not a hardware-independent FPS promise. No map rendering pipeline or alignment rewrite was introduced. Full-map resizing uses the existing Leaflet resize observer.

## Security / dependency review
No dependency added or changed. No native game process inspection, injection, hooking, memory access or remote game commands introduced. Relay capabilities remain marker-write and session-read/revoke only. Server configuration stays private under $profile; desktop profiles explicitly whitelist non-secret fields. Diagnostics contain generic messages, counts and timestamps, not tokens. Safety lockout affects only the current bridge, not offline editing. Existing app/runtime signing is unchanged.

- No whole-server player tracking, vanilla automatic player discovery, GM commands, persistent shared operation or multi-unit live feed is claimed.
