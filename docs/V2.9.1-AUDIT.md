# v2.9.1 pre-change audit — 11 October 2026

Baseline: origin/main 5b8b7bd; all 88 planner tests pass with loopback networking enabled. No uncommitted changes at audit start.

## Architecture and evidence
- planner/local-bridge.js createReceiver: explicit loopback POST /marker, random 32-character writer credential, strict 2KB schema, rate limits, seven-second stale removal. install validates IPC sender and owns shutdown.
- planner/free-bridge.js createFreeBridge: owns a transient relay and cloudflared helper. Planner pairing/polling stays on loopback; game receives public HTTPS URL. No hosting account required.
- planner/remote-bridge.js createRemote: POST /sessions creates writer/read credentials; GET /session polls; DELETE revokes. Current retry loop is unbounded; 401 clears state without explaining expiry. Old responses have limited ordering checks.
- planner/bridge-runtime/relay.js and relay/server.js: ephemeral sessions, separate 128-bit writer / 256-bit reader tokens, one-hour lifetime, 2KB payloads, latest-position coalescing, seven-second stale timeout. No remote game commands.
- reforger-mod/https-bridge/.../JSOC_ORBAT_HostBridge.c Connect/Send: Replication.IsServer guard exists, but GetPlayerController/GetControlledEntity and pause-menu pairing require a host player. This is not a headless dedicated implementation.
- planner/local-bridge-layer.js: separate transient Leaflet layer; does not touch plan state, undo, exports or autosave. Applies established +50m imagery offset only on display.
- planner/bridge: separate simulation protocol already has batching, stable IDs, revisions, authorization fixtures and lockout tests. This is simulated, not a live whole-server feed.

## Support classification
Working/user-tested: Host Local, GeForce NOW via HTTPS tunnel, single-character position rendering.
Existing but not verified dedicated: server-authority guard and REST API transport.
Requires changes: headless initialization/configuration, explicit server-selected entity, retry lifecycle, endpoint profiles and useful errors.
Not implemented: whole-server tracking, shared operations, remote administration, commands into the game.

## Minimal implementation sequence
1. Preserve legacy local mode and wire protocol; add validated secret-free connection profiles separately from mission data.
2. Harden remote polling, bounded backoff, cancellation, stale detection, diagnostics and protocol negotiation.
3. Extend relay with optional v2 single-entity messages, session/entity identity, ordered sequence and scoped lockout. Keep legacy marker messages.
4. Add opt-in dedicated sender reading server-local profile config and selecting one named entity. No player enumeration; no credentials in Workshop resources.
5. Extend existing settings and Sarge; run baseline regression plus actual HTTP adapter and packaged Electron tests.

## Risks and validation gates
Dedicated Enfusion compilation and real hosting require Workbench/server access and remain experimental until performed. Match installed game API; supported REST/JSON/world APIs only. Session credentials expire; retry must not silently create a new session. Stable ID is an administrator-chosen entity key within a paired session, not a callsign. Changing selected entities requires a new session. A named scenario entity needs an administrator-maintained scenario; arbitrary vanilla player discovery is out of scope. Public tunnel reachability is variable and ephemeral. No native game-process access, inbound gameplay-port assumptions, or secret persistence in plans.

Tests: all existing tests before/after; profile CRUD and validation; HTTP authorization/expiry, protocol/size/schema errors, ordering, lockout, retry bounds, duplicate start, shutdown; packaged UI offline startup, profile persistence, live marker, unchanged plan and reconnect/stop. Real Enfusion is a separate gate, never inferred from Node adapter tests.
